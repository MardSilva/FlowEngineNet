# Flow Engine 0.1 release review

Review date: 2026-08-15.

## Outcome

The `0.1.0-rc.1` source tree satisfies the Flow 0.1 research definition of done within the explicitly documented scope. `VersionPrefix` is `0.1.0`, package creation is disabled, and no package is published.

This is not a declaration that Flow is a standard, an EPUB reading system, an archival format, a WCAG-conformant reader, a trusted signature system, or a production pagination engine.

## Conformance

The twelve original numbered vectors are implemented in order in `SemanticConformanceTests`:

1. stable document identity;
2. duplicate node rejection;
3. anchor resolution;
4. presentation-independent hash;
5. content-sensitive hash;
6. independent heading typography;
7. navigable semantic TOC;
8. one-column small viewport;
9. reader font override;
10. figure/caption ownership;
11. footnote resolution;
12. semantic, escaped HTML.

Two additional conformance guards verify the approved production dependency graph, `VersionPrefix`, disabled package creation, and XML documentation generation. See [conformance.md](conformance.md).

## Dependency isolation

The verified direct dependency graph is:

```text
Flow.Core
  └─ (none)

Flow.Documents ──> Flow.Core
Flow.Layout ─────> Flow.Core + Flow.Documents
Flow.Rendering ──> Flow.Documents + Flow.Layout
Flow.Rendering.Html ──> Flow.Rendering
Flow.Security ───> Flow.Documents
Flow.Epub ───────> Flow.Core + Flow.Documents
Flow.Cli ────────> Flow.Documents + Flow.Layout + Flow.Rendering.Html + Flow.Security
```

The semantic domain has no reference to layout, HTML, EPUB, CLI, operating-system UI, PDF, or browser APIs. EPUB and HTML remain outward adapters. The CLI has no EPUB reference until it exposes an actual import operation.

## Clean-directory validation

A new temporary directory was populated from the working tree while excluding `.git`, every `bin`, every `obj`, and `.vs`. The following commands then ran from that directory, in the same order used by CI:

```powershell
dotnet restore Flow.sln
dotnet format Flow.sln --verify-no-changes --no-restore
dotnet build Flow.sln --no-restore
dotnet test Flow.sln --no-build
```

Result:

- restore succeeded for all 16 projects;
- formatting verification succeeded with no changes;
- build succeeded with 0 warnings and 0 errors;
- 134 tests passed, 0 failed, 0 skipped;
- generated XML documentation accompanied the public assemblies.

The original local 0.1 clean validation ran on Windows with .NET SDK 10.0.302. The active development toolchain was later advanced to 10.0.400 in `global.json`; this historical result is not rewritten as if it had used the newer SDK. `.github/workflows/ci.yml` applies the repository's current pinned SDK and the same validation sequence to both `windows-latest` and `ubuntu-latest`; Linux CI becomes external evidence only after the workflow runs on GitHub.

## Release boundary

The complete exclusions and interoperability gaps are maintained in [known-limitations.md](known-limitations.md). In particular, 0.1 does not include a Reader, PDF output, production pagination, package publication, broad EPUB support, EPUB CLI import, signature trust, or an accessibility-conformance claim.
