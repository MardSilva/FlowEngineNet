# Flow 0.2 EPUB cycle review

Review date: 2026-09-17.

## Outcome

The EPUB cycle is complete for the documented 0.2 alpha scope. The source repository can be presented publicly as an experimental implementation that imports a bounded EPUB subset into the Flow semantic model and produces deterministic Flow JSON and HTML outputs.

This outcome does not make Flow an EPUB reading-system implementation, an EPUB conformance checker, a production Reader, an accessibility-certified product or a replacement for EPUB. No package or executable release is published by this review.

## Evidence

The versioned test corpus covers generated EPUB 2 and EPUB 3 fixtures, malformed and malicious inputs, navigation, metadata, spine order, links, images, notes, tables, SVG, MathML, CSS and internationalized inline content. Optional EPUBCheck evidence remains separate from Flow's own qualification result.

One legally obtained, DRM-free, locally supplied reflowable publication completed the large-publication pipeline. Two automatic repetitions preserved the same canonical hash, reading order, anchors and structural evidence. The run imported 39 chapters, 3,911 semantic nodes, 18 assets and more than 1.1 million characters with no validation error or measured lost fidelity unit. Assisted review then approved the beginning, middle, end, TOC, links, images, notes and tables at 390 x 844 and 1600 x 1000 CSS-pixel viewports.

The licensed source, generated book and review screenshots remain outside the repository. Public documentation records only aggregate evidence and reproducible procedure.

## Public interface

The CLI keeps commands, options, JSON fields and diagnostic codes invariant. Human-readable terminal output uses resource catalogs for `en-US` and `pt-BR`; `en-US` is the default, and unsupported values fail with an English fallback message. Corpus qualification, the automatic large-publication gate and assisted-review generation are available as explicit commands. The gate requires an expected SHA-256 plus legal-use and DRM-free declarations, while review artifacts must stay outside the repository. Existing operational outputs require `--force`; a destination-specific file lock prevents concurrent Flow writers, and recognized interrupted transactions require `--resume`. Read-only status and UUID-bound cleanup commands expose local diagnosis without granting broad deletion authority. Recovery receives a new execution ID and restarts from verified source data instead of trusting partial output. The optional ASCII banner has no effect on generated files. Output stays usable without ANSI color support. The CLI can also be packed as an isolated local .NET tool, and CI smoke-tests that installed launcher on Windows and Linux without publishing it. A separate local release build requires two normalized packages to match before generating SHA-256 checksums, a CycloneDX SBOM and a validation manifest. Its versioned dry-run adds unsigned in-toto/SLSA provenance, while a final CI job compares the portable Windows and Linux hashes without uploading the package or creating a release.

The multi-file HTML book provides responsive chapters, a separate TOC, chapter-local notes, contained media, table scroll regions, themes and localized generated controls. It is a demonstration and publication artifact, not the planned Reader's internal storage format.

## Release boundary

Public descriptions may state that Flow:

- imports the documented EPUB subset under bounded, offline processing rules;
- preserves stable semantic IDs, reading order and supported content through serialization, layout and HTML rendering;
- produces deterministic canonical hashes independent of presentation;
- exposes explicit diagnostics and fidelity evidence when source constructs are unsupported or approximated;
- has completed one local large-publication qualification cycle.

Public descriptions must not claim that Flow opens every EPUB, passes EPUB 3.3 conformance, meets WCAG, reproduces publisher layout exactly, supports DRM, or is ready for production reading devices.

## Next research cycle

The next recommended increment is a separate PDF-to-Flow research plan. It should begin with born-digital PDFs, typed extraction evidence and explicit loss diagnostics. OCR, scanned documents, physical pagination and production PDF rendering remain separate decisions.
